# usan の判定規則

## 処理モデル

入力ごとに次の 3 段で処理する。状態は入力ファイルごとに初期化する(ファイルをまたいで文脈を持ち越さない)。

1. **UTF-8 デコード**: 不正なバイト列は「maximal subpart」ごとに U+FFFD 1 個に置換する(Unicode 標準 §3.9 の推奨方式。WHATWG と同じ)。
   正当なバイト範囲は Unicode 標準 Table 3-7(Well-Formed UTF-8 Byte Sequences)に従う。
   不正を検出したら、そこまでの未完シーケンスを U+FFFD 1 個として出し、検出を起こしたバイトは新しいシーケンスの先頭として再評価する。
   チャンク境界で分断された正当なシーケンスは正しく復元する。EOF で未完のシーケンスは U+FFFD 1 個にする。
2. **段階 1(無条件除去)**: 下記「段階 1」の P 行に該当する文字を捨てる。残った列を「段階 1 列」と呼ぶ。
3. **段階 2(文脈判定)**: 段階 1 列の各文字のうち下記「段階 2」の C 行に該当するものを、文脈で残すか捨てるか決める。それ以外はそのまま出力する。

不正 UTF-8 を素通しにしない理由: 冗長エンコード(例 `F0 82 80 8B` = 冗長な U+200B)を寛容に復号する下流で除去を迂回されるため。
エラー終了にしない理由: フィルタとして途中で止まるより、可視の U+FFFD に置き換えて全体を出す方が扱いやすいため。

## 用語

| 用語 | 定義 |
|---|---|
| prev | その時点で出力済みの最後の文字。出力が空なら「なし」 |
| base | 出力済みの文字を末尾から遡り、transparent に属さない最初の文字。無ければ「なし」 |
| next | 段階 1 列での次の文字。EOF なら「なし」 |
| transparent | Script=Inherited ∪ Emoji_Modifier(U+1F3FB..1F3FF)。結合記号・VS・ZWJ/ZWNJ・肌色修飾子を含む |
| join_context | 次の和集合から Default_Ignorable_Code_Point を引いた集合: (a) Joining_Type が D/L/R/C の文字を 1 つでも持つ Script の全文字、(b) ccc=9(Virama)の文字を 1 つでも持つ Script の全文字、(c) Joining_Type が D/L/R/C の個々の文字(U+0640 TATWEEL など Common のもの)。(a)(b) の Script 集合からは Common/Inherited/Unknown を除く |
| strong_rtl | Bidi_Class が R または AL の文字から Default_Ignorable_Code_Point を引いた集合(RLM・ALM 自身は含まない) |
| 段落区切り | Bidi_Class=B の文字: U+000A, 000D, 001C-001E, 0085, 2029(固定。表にしない) |
| rtl_seen | 現在の段落(最後に出力した段落区切りの後)で、strong_rtl の文字をすでに出力したかどうか |
| ext_pict | Extended_Pictographic |
| variation_pairs | StandardizedVariants.txt と emoji-variation-sequences.txt に載る (基底, VS) の組 |
| tag run | 段階 1 列で連続する U+E0020..E007F の並び。U+E007F を含んだ時点で終わる |

判定は「出力上の直前(prev/base/rtl_seen)」と「段階 1 列の次(next)」で行う。
こうすると、出力に残った文脈依存文字はすべて出力上の文脈によって正当化され、処理は冪等になる(clean.zig の性質テストで確認する)。
冪等性は、next として参照される文字(join_context・ext_pict・strong_rtl・ハングル中声・モンゴル文字 a/e)と段落区切りが除去対象にならないことに依存する。
そのため、ext_pict・Unified_Ideograph・variation_pairs の基底は Default_Ignorable と交差しないことを props.zig のテストで検査し、join_context と strong_rtl は生成時に Default_Ignorable を差し引く。

## 段階 1: 無条件除去(P 行)

実装上は「Default_Ignorable_Code_Point に属し、かつ段階 2 の対象でない文字は捨てる」の 1 判定で P1-P8 をすべて覆う。

| # | 対象 | コードポイント | 扱い | 理由 |
|---|---|---|---|---|
| P1 | Bidi 埋め込み/上書き/隔離 | 202A-202E, 2066-2069 | 除去 | Trojan Source 対策。対応が取れていても除去する |
| P2 | ZWSP / WJ / 不可視演算子 / 廃止書式文字 / 未割当 | 200B, 2060-2065, 206A-206F | 除去 | 書記素を構成しない。タイ語等の ZWSP による改行ヒントも除去される |
| P3 | SHY | 00AD | 除去 | |
| P4 | CGJ | 034F | 除去 | |
| P5 | ZWNBSP / BOM | FEFF | 除去。ただし**まだ何も出力していない時点で始まる入力の先頭の 1 文字目**に限り残す | 出力の先頭に来る BOM は符号化の署名であり不審でない。それより前の入力が何かを出力していれば BOM は出力の途中に来るので除去する(前の入力が空・読めない・すべて除去された場合は残す) |
| P6 | ハングルフィラー(単独で使われるもの) | 3164, FFA0 | 除去 | 不可視の識別子・名前に悪用される |
| P7 | クメール独立母音記号(非推奨) | 17B4, 17B5 | 除去 | Unicode が使用非推奨としている |
| P8 | 速記書式制御 / 楽譜書式 / 未割当 DI | 1BCA0-1BCA3, 1D173-1D17A, FFF0-FFF8, E0000-E0FFF のうち段階 2 の対象外(E0001 LANGUAGE TAG を含む) | 除去 | 書記素を構成しない(GCB=Control) |

P5 の先頭判定は、Filter に最初に push された文字が FEFF で、かつ `keep_leading_bom` が真のときに残す。
`keep_leading_bom` は、CLI がその入力を始める時点でまだ 1 バイトも出力していない(検査モードでは破棄用 Writer に 1 バイトも書いていない)ときだけ真にする。

## 段階 2: 文脈判定(C 行)

| # | 対象 | コードポイント | 残す条件(これ以外は除去) |
|---|---|---|---|
| C1 | ZWJ / ZWNJ | 200D, 200C | 上から順に評価する。(1) prev が ZWJ/ZWNJ なら除去。(2) base ∈ join_context なら残す。(3) next ∈ join_context なら残す。(4) ZWJ に限り、base ∈ ext_pict かつ next ∈ ext_pict なら残す。(5) 除去 |
| C2 | VS1-16 / モンゴル FVS1-4 | FE00-FE0F, 180B-180D, 180F | (prev, その VS) ∈ variation_pairs |
| C3 | VS17-256 | E0100-E01EF | prev ∈ Unified_Ideograph |
| C4 | TAG | E0020-E007F | tag run 単位で判定する。run 開始時の prev が U+1F3F4 で、run が「tag spec + U+E007F」であり、tag spec(各文字から 0xE0000 を引いた ASCII)が `([a-z]{2}\|[0-9]{3})[a-z0-9]{1,4}` に一致する場合だけ run 全体を残す。それ以外は run 全体を除去 |
| C5 | ハングル初声フィラー | 115F | next ∈ 1161-11A7 ∪ D7B0-D7C6(中声。U+1160 は含めない) |
| C6 | ハングル中声フィラー | 1160 | prev ∈ 1100-115E ∪ A960-A97C(初声。U+115F は含めない) |
| C7 | モンゴル母音分離記号 MVS | 180E | prev ∈ 1800-18AF かつ next ∈ {1820, 1821} |
| C8 | Bidi マーク | 200E LRM, 200F RLM, 061C ALM | 上から順に評価する。(1) prev が LRM/RLM/ALM なら除去。(2) rtl_seen なら残す。(3) next ∈ strong_rtl なら残す。(4) 除去 |

join_context は、アラビア系のように文字が連結する筆記体系(Joining_Type が D/L/R/C の文字を持つ Script)と、インド系・東南アジア系のように Virama(ccc=9)を持つ筆記体系の全文字、および Joining_Type が D/L/R/C の個々の文字である。
C1(1) と C8(1) により、連続する joiner やマークは高々 1 個しか残らない。2 値の並びによる情報の埋め込みを防ぐためである。

各行の決定理由:

- C1: 「文脈で判定」の実体として、スクリプトの分類を UCD から機械的に導出する(Joining_Type を持つ筆記体系=アラビア系、Virama を持つ体系=インド系・東南アジア系)。
  IDNA の CONTEXTJ 規則(RFC 5892。virama 直後のみ許可)は採らない。ベンガル語の RA+ZWJ+virama、アラビア語の語末 ZWJ など正当な用法を落とすため。
  base 側・next 側のどちらかが join_context なら残す(語末・語頭の用法を拾うため)。(1) により、連続する joiner は高々 1 個しか残らず、ZWJ/ZWNJ の 2 値列による情報の埋め込みを防ぐ。
  (4) は UAX #29 GB11(ExtPict Extend* ZWJ × ExtPict)に対応する。RGI に無い組み合わせ(例: 🍕‍🐶)も GB11 上は 1 書記素なので残す。
  ラテン文字間(独語の合字抑止 ZWNJ を含む)は除去される。これは意図した方針である。
- C2: 正確な組の表(2179 組、約 8.7 KB)を持つ。基底集合だけで判定する案より厳密で、サイズ差は小さい。
  U+1F3F4 は emoji-variation-sequences に無いため、`🏴 FE0F` の FE0F は除去される(後続のタグ旗は C4 で有効のまま)。
- C3: IVD の正確な組(約 4 万組)は表が 100 KB 超になり、IVD は UCD と別の周期で更新されるため採らない。
  UTS #37 は IVS の基底を Unified_Ideograph と定めている。IVD 2026-08-03 版の全 39509 シーケンスの基底は Unified_Ideograph であり、使用 VS は E0100..E011F に収まる。E0100-E01EF の全域を許す。
- C4: CLDR の subdivision 妥当性データは持たず、`unicode_subdivision_id` の構文(region 2 英字 or 3 数字 + suffix 1-4 英数字)だけ検査する。
  tag spec は最大 7 文字なので、run のバッファは最大 7 文字で足りる。8 文字目が E007F でなければその時点で無効と確定する。
  tag run の途中にある段階 1 の除去対象(例: E0001)は段階 1 で消えるので run を分断しない。
- C5/C6: ハングル字母の結合列(古ハングル等)での正当な用法を残す。`115F 1160` の組(空白に見える 1 書記素)は両方除去する。
- C7: MVS はモンゴル語で語末の a/e(U+1820/1821)の直前に置かれる。
- C8: Bidi マークの正当な用途は、RTL 文字を含む段落の中で約物・数字・LTR 語の表示位置を整えることである。
  そこで「同じ段落にすでに RTL 文字が出ている」か「直後が RTL 文字」の場合だけ残す。
  - 採用理由(コスト): 追加の状態は rtl_seen の 1 ビットだけで、先読みは既存の 1 文字で足りる。表は strong_rtl の 138 レンジ(約 1.1 KB)。
    rtl_seen が真になった後は、段落区切りまで表を引かなくてよい。
  - 防げるもの: RTL 文字を含まない段落(ソースコードの識別子、ラテン文字だけの文など)に紛れたマークは除去される。
    (1) により、連続するマークは高々 1 個しか残らない。
    Trojan Source の並べ替え攻撃に使われる埋め込み・上書き・隔離(P1)は無条件に除去する。マークは中立文字と弱い文字の向きにしか影響しない。
  - 既知の取りこぼし: RTL 文字より前にあり、直後が RTL 文字でないマークは除去される。
    例: ヘブライ語の段落を数字で始めるために先頭に置く RLM(`RLM 123 שקל`)。除去されると表示が変わることがある。
    これを拾うには、段落末まで先読み(行単位のバッファリング)が要るため採らない。
  - 却下した案: 前後 1 文字に strong_rtl があるときだけ残す案。`שלום!RLM` のように約物の後に置く典型的な用法を落とすため採らない。

## 状態機械(filter.zig)の組み方

- 状態は prev・base・rtl_seen・保留中の 1 文字・tag run バッファ(最大 7 文字)・先頭判定フラグ・`removed` だけで、O(1) メモリ。
- next 待ち(保留)が要るのは C1(C1(1)(2) で決まる場合は待たない)、C5、C7(prev が 1800-18AF でなければ待たずに除去)、C8(C8(1)(2) で決まる場合は待たない)。保留は常に高々 1 文字。
  保留中は何も出力しないので、保留した文字を確定させるときの prev・base・rtl_seen は保留した時点のままである。
- 新しい文字が来たら、まず段階 1 で除去するか判定し、残るならば保留中の文字をその文字を next として確定させ、次に tag run の処理、最後に新しい文字の分類を行う。
- `finish` では保留中の文字を next=なしで確定し、終端していない tag run を捨てる。
- tag run は run 開始時の prev を見て、spec を 1 文字ずつ構文検査する。破綻した時点で破棄モードに入り、E007F か非 TAG 文字で run を終える。
- 出力のたびに prev を更新する。base は出力した文字が transparent でないときだけ更新する。
  rtl_seen は、段落区切りを出力したら偽に、strong_rtl の文字を出力したら真にする(真の間は表を引かなくてよい)。
- 1 文字でも捨てたら `removed` を真にする(tag run を捨てた場合も含む)。

## 対象外(そのまま通す)

- 結合記号(U+0301 等)、肌色修飾子、Regional Indicator
- NBSP や各種空白(U+00A0, 2000-200A, 202F, 205F, 3000)
- C0/C1 制御文字、U+2028/2029、私用領域、非文字(U+FFFE 等)、U+FFFC
- 改行コード(変更しない)
